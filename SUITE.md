# TLQ kernel v0.1 — regression suite

Run: `python3 run_suite.py`. It uses real pytest if installed, otherwise a minimal pytest-compatible runner. Current status (v0.3): **66 passed, 0 failed** (47 scripted + 15 search + 4 v0.3). The blind case lives in `tests/blind/`: pre-registration, runs, independent evaluator, results.

## Layout

| Path | Contents |
|---|---|
| `tlq/kernel.py` | Generic machinery: obligations (S/L/D/V), transformations (map, lift, declared preservation, obligations, executable flag), branching derivations, ledger, rejection, confluence. **No case knowledge.** |
| `tlq/finite.py` | Finite problems $P=(W,E,T)$: world outcomes; **sites** (program + record store; `memory` = $\mathscr A(n,n)$) vs **evaluations** (events generated by Γ); world reads vs record reads; owners; solution concept. |
| `tlq/rules_finite.py` | Rules for finite teams and games (general over their class). |
| `tlq/liquidation.py` | The liquidation class and the round-2 chain. |
| `tlq/registry.py` | Generic rule instantiators keyed on problem kind and structure (never problem identity). |
| `tlq/search.py` | Derivation search, blocked-step diagnosis (REFUTED / CONSERVATIVE / UNESTABLISHED), status classification, cross-derivation consistency audit. |
| `tests/cases.py` | **Problem builders only.** No solutions are encoded there. |
| `tests/test_*.py` | Each case has: the valid derivation(s); the expected transformation sequence; certificate kinds and statuses; the ledger; the expected solution (checked against an independent oracle where one exists); and at least one **invalid derivation the kernel must reject**, with the specific obligation named. |

## What the prototype does not yet do

- **Derivations are scripted, not discovered.** The kernel checks, composes and lifts; it does not search for derivations. The next adversary is to make it *find* each case's derivation.
- **Rule classes are narrow.** Liquidation is a symbolic class. COMMON_INFO handles fixed events with one evaluation per site. PBE is reached only through full-support noise, so there is no genuine PBE solver: the record-arrow leak is refused, not solved. BEHAVIOURAL_OPT certifies only by multistart agreement.
- **D obligations are contradicted only by explicit world-model fields.**

## v0.2: derivation search (`tests/test_search.py`)

The searcher receives only the root problem and the registry. A static test checks that neither `search.py` nor `registry.py` mentions any case.

- Every kept edge passed the kernel's checks.
- Every kept terminal passed its a-posteriori obligations and certifies at least soundness.
- Derivations are compared under the task's own solution equivalence.

Blocked steps get one of three verdicts:

| Verdict | Meaning |
|---|---|
| **REFUTED** | A value gap or a concrete violation was found. |
| **CONSERVATIVE** | Not certified, but nothing was lost in this instance. |
| **UNESTABLISHED** | Not diagnosable. |

Search statuses:

| Status | When it is returned |
|---|---|
| `FOUND` | At least one certified derivation. |
| `NOT_ESTABLISHED` | No certified derivation, and a reason is given: an unrefuted block, a missing solved class, a dead end, or an exhausted budget. |
| `NO_DERIVATION_IN_REGISTRY` | Only when every blocked step was refuted and nothing was left unexplored. |
